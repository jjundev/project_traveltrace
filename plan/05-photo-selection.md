# 05 · 사진 선택 (권한 · MediaStore · 선택 그리드)

> 갤러리에서 여행 사진을 다중 선택하는 화면. MediaStore 기반 + 미디어 권한, 최대 ~100장, 안정적 `_ID` 확보.

- **Epic**: Selection
- **Depends on**: 02, 03, 04
- **PRD**: §4.1, §9 #3·#6, §8(광범위 권한 트레이드오프)
- **Prototype**: SELECT 화면(기간 카드, "선택한 사진 N장", 3열 그리드, 탭 토글, "분석 시작")

## 목표
사용자가 여행 사진을 다중 선택하고, 각 사진의 **안정적 `MediaStore _ID` 핸들**을 확보해 다음 단계(EXIF·분석)로 넘긴다.

## 범위
- **In**: 권한 요청/거부 처리, MediaStore 이미지 쿼리·페이징, 3열 썸네일 그리드, 다중 선택 토글, 선택 수/상한 표시, 기간 요약, "분석 시작" → Analyze 전환.
- **Out**: EXIF 추출(06), 해시(07), 분석(10). "여행 기간 변경" 상세 필터 UI는 스텁(향후).

## 권한 (§4.1, §9 #6)
- [ ] `READ_MEDIA_IMAGES`(API 33+) 요청. 거부 시 안내(설정 이동 유도) + 기능 차단 화면.
- [ ] `ACCESS_MEDIA_LOCATION` 요청(06에서 원본 GPS 읽기용). 여기서 함께 확보하되 실제 사용은 06.
- [ ] Android 14+ "선택한 사진만 접근(partial access)" 시나리오 처리: 부분 권한이면 "더 선택/전체 허용" 재요청 흐름.
- [ ] **트레이드오프 명시(README·앱)**: `READ_MEDIA_IMAGES`는 Play 정식 배포를 막는 선택(sideload 가족용에서 수용).

## MediaStore (§9 #3 — Photo Picker 대신 MediaStore 채택)
- [ ] `MediaStore.Images` 쿼리로 이미지 목록(썸네일·`_ID`·`DATE_TAKEN`·`DISPLAY_NAME`) 로드. **채택 사유는 캐싱/재조회를 위한 안정적 `_ID`**(Photo Picker의 영구 grant는 안정적 `_ID`를 못 주고 재선택을 강제).
- [ ] 썸네일 로딩: `ContentResolver.loadThumbnail`/`Glide` 등으로 비동기·메모리 안전. 스크롤 성능(수백~수천 항목) 대비 페이징(`RecyclerView` + paging).
- [ ] 3열 `RecyclerView` 그리드(프로토타입 3열 6dp gap), 선택 시 파란 체크 오버레이 + 미선택 dim(프로토타입 `boxShadow`/opacity 재현).

## 선택 UX (프로토타입 SELECT)
- [ ] 다중 선택 토글, **최대 ~100장** 상한(초과 시 안내). 프로토타입 문구 "최대 100장 · 탭하여 제외".
- [ ] 상단 "선택한 사진 **N**장"(파란 강조) 실시간 갱신.
- [ ] 기간 요약 카드("2024. 6. 12 – 6. 15 · 사진 94장" 형태) — 선택/DATE_TAKEN 기반 자동 계산. "변경"은 스텁.
- [ ] "분석 시작" → 선택 `_ID` 목록을 공유 VM/리포지토리에 적재 후 Analyze로 전환(03 인자 계약).

## 완료 조건 (DoD)
- [ ] 권한 허용/거부/부분허용 3경로 모두 사용자 안내가 나오고 앱이 죽지 않음.
- [ ] 수백 장 갤러리에서 스크롤이 버벅이지 않음(썸네일 재활용·페이징).
- [ ] 선택 상한·카운터·기간 요약이 정확.
- [ ] "분석 시작" 시 선택 `_ID` 목록이 다음 화면으로 안정적으로 전달(대용량도 Bundle 직렬화 없이).

## 리스크·주의
- Android 14 partial photo access가 기본일 수 있음 — "전체 허용" 유도 UX 없으면 갤러리 일부만 보임.
- 상한 100장은 §5 성능 예산과 연동(동시 4·타임아웃 30s). 초과 허용 정책은 10과 합의.
- 썸네일 대량 로딩 OOM 주의(비트맵 크기 제한·캐시).
