# 15 · 여행 저장 · 캐싱 · 오프라인 재생

> 분석 결과를 "2024 파리 여행" 같은 여행 단위로 저장하고, 홈에서 다시 열어 재생한다. 저장 메타데이터로 AI 호출 없이 재생(지도 타일은 네트워크 필요).

> **상태: 🟡 대부분 완료.** 저장·목록·열기·삭제·빈 상태는 S1 이, 캐시 재사용과 오프라인
> 한계 안내는 S8 이 구현했다. 남은 것은 **여행 이름 입력 UX**(현재는 "YYYY년 M월 여행"
> 자동 명명) 하나다.

- **Epic**: Persistence
- **Depends on**: 04, 10, 12
- **PRD**: §4.7 저장·캐싱, §5 오프라인, §9 #11, §3(마지막 시나리오)
- **Prototype**: 홈 여행 목록(파리/제주 카드, empty state), `openTrip`(저장 여행 열기)

## 목표
사용자 시나리오 6번("결과를 '2024 파리 여행'으로 저장하고 나중에 다시 보여준다")을 완성. 재분석·재호출 없이 저장 여행을 재생.

## 범위
- **In**: 여행 저장(이름 지정)·목록·열기·삭제, 홈 화면 목록/빈 상태, 캐시 재사용, 저장 메타로 오프라인 재생, 오프라인 지도 한계 안내.
- **Out**: 분석 파이프라인(10), 지도/리플레이 렌더(12·13), 스키마 정의(04 — 여기선 사용).

## 여행 저장·홈 (§4.7, 프로토타입 HOME)
- [x] 분석 완료 결과(10)를 Trip으로 확정 저장(이름·기간·커버·스톱·분류·costSpent).
- [ ] 이름 입력 UX(기본값 "YYYY 도시 여행" 제안) — 현재는 "YYYY년 M월 여행" 자동 명명.
- [x] 홈 목록: 저장 여행 카드(썸네일 헤더·제목·"82장 · 4일 · 2024. 6" 메타). 프로토타입 카드 레이아웃 재현.
- [x] **빈 상태**(empty): "첫 여행을 만들어 보세요" + 안내 + "새 여행 만들기" CTA(프로토타입 `emptyHome`).
- [x] 여행 카드 탭 → Map 직접 진입(`openTrip`, 03·12). 삭제 UX(04 cascade).

## 캐싱 재사용 (§4.7 — 핵심)
- [x] 같은 사진은 (`_ID`+콘텐츠 해시) 캐시로 재분석/재호출 방지(04·07·10). 다른 여행에서도 hit.
- [x] 캐시는 **기기 로컬 한정**(`_ID` 기기 내 안정) — 기기 변경/초기화 후 재분석 가능함을 README·앱에 명시.

## 오프라인 재생 (§5 오프라인 — 정확한 표현)
- [x] 저장 여행은 **저장 메타데이터(좌표·시각·랜드마크명)로 AI 호출 없이 재생** 가능.
- [x] **단, 지도 타일(2D·3D 모두)은 네트워크 필요** — 진정한 오프라인 지도가 아님. 연결이 없으면 **빈/실패한 지도 위 폴리라인만** 그려짐. 이 한계를 재생 화면에서 안내(오해 방지).
- [x] 오프라인 상태 감지 → "지도 타일을 불러올 수 없어요, 경로는 표시돼요" 류 안내.

## 완료 조건 (DoD)
- [ ] 분석 결과를 이름 지정해 저장 → 앱 재시작 후에도 홈에 유지.
- [x] 저장 여행 열기 → AI 호출 0회로 지도·리플레이 재생(비용 로그 확인).
- [x] 같은 사진 재분석 시 캐시 hit(네트워크 콜 0).
- [x] 빈 상태/목록 상태가 프로토타입대로 표시.
- [x] 오프라인에서 지도 타일 실패해도 폴리라인 재생 + 한계 안내(크래시 없음).

## 리스크·주의
- "오프라인 재생"을 과장 표현하지 말 것 — 지도 타일은 네트워크 필요(§5). UI 카피 정확성 중요.
- detach/분류 편집 상태의 SoT를 04와 통일(저장 여행 재생 시 편집 반영 여부, 04·13 리스크).
- 기기 초기화 후 `_ID` 불안정으로 캐시 무효화 — 사용자에게 재분석 가능성 안내.
